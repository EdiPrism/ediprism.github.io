ASC X12 Three-Layer Envelope Anatomy (ISA → GS → ST)

Every compliant ASC X12 file wraps business payloads inside three nested control envelopes validated independently by clearinghouses and VANs:

ISA*00*          *00*          *ZZ*SUBMITTERID    *ZZ*RECEIVERID     *261112*1430*^*00501*000000901*0*P*:~
  GS*HC*SUBMITTER*RECEIVER*20261112*1430*901*X*005010X222A1~
    ST*837*0001*005010X222A1~
      ... [Business Loops & HL Hierarchy] ...
    SE*42*0001~        <-- SE-01 (42) counts ST..SE inclusive; SE-02 matches ST-02
  GE*1*901~            <-- GE-01 (1) counts ST/SE sets in group; GE-02 matches GS-06
IEA*1*000000901~       <-- IEA-01 (1) counts GS/GE groups; IEA-02 matches ISA-13

Frequently Asked Engineering Questions

How does an X12 parser discover delimiters without a schema?

In a compliant 106-byte ISA segment, byte index 3 defines the element separator (typically *), byte 104 defines the composite component separator (typically :), and byte 105 defines the segment terminator (typically ~). For broken chat-pasted headers under 106 bytes, EdiPrism uses heuristic token scanning.
