100% Offline Reference FIX SBE Reference

FIX SBE Wire Byte Offsets, Alignment Gaps & actingBlockLength Evolution

In ultra-low-latency C++, Rust, and JVM trading systems, miscalculating a single explicit offset attribute or blockLength inside an <sbe:messageSchema> XML file shifts every downstream repeating <group> and <data> cursor on the wire.

1. Standard 8-Byte messageHeader + Root Block Layout

Wire OffsetComposite MemberPrimitiveDecoder Role
B0..B1blockLengthuint16 LEActing byte length of the fixed root block on the wire (excludes the 8B header, groups, and varData)
B2..B3templateIduint16 LESelects the target <sbe:message id="..."> decoder
B4..B5schemaIduint16 LEVerifies venue <sbe:messageSchema id="...">
B6..B7versionuint16 LEActing schema version (actingVersion) for extension field gating

2. Four Non-Negotiable Wire Ordering & Evolution Rules

  • Zero-Byte Constants: Any <type presence="constant"> (such as exponent = -9 inside PRICE9) consumes 0 bytes on the wire; only the 8-byte int64 mantissa is transmitted.
  • Alignment Padding Holes: Setting offset="16" after a 12-byte prefix leaves B12..B15 unmapped — always zero-initialize outbound buffers so stack data never leaks onto exchange sockets.
  • Strict Section Order: Every SBE message must serialize Root Fields → Repeating <group>s → Variable <data>. Placing <data> ahead of a <group> breaks deterministic cursor stepping.
  • Backward-Compatible Extensions: Append new root fields at offset ≥ oldBlockLength with sinceVersion > oldVersion. Replay decoders advance to groups via rootStart + actingBlockLength regardless of newer fields.
